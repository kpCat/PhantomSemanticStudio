# Предлагаемая реализация и минимальные границы

## Core: определённый результат, а не случайная заглушка

1. Имея exact/prefix/suffix PATTERN, `PackPreview` детерминированно собирает только подходящие clean non-mature TEMPLATE с тем же `act` и допустимым отношением/register. **Не ограничивается первым TEMPLATE**, если для него отсутствует обязательный runtime контекст.
2. `SafeRender`/аналог: неизменяемая копия текста реально выбранного шаблона. Безопасно вернуть сырой текст без placeholders. `{value}` допускается только с реально захваченным валидным фрагментом из input, если конкретная pattern-ветка его поддерживает; не придумывать значения. `{name}`, `{interest}`, `{memory}` без реальных источников — **не рендерить**. Запрещены `ТестовыйФантом`, `[интерес не задан]`, `[память не подключена]` внутри положительных PACK ответов.
3. При отсутствии контекстно пригодного первого шаблона пробовать следующий. Если все eligible требуют неизвестных данных — отделить это от `NO_PACK_MATCH` и от настоящей `FUNCTIONAL_OR_MEMORY_UNSUPPORTED` (например `TEMPLATE_CONTEXT_UNAVAILABLE`). Сохранить match PatternId/act/topic и диагностическое объяснение, но не выдавать пустоту как успешный ответ.
4. Для настоящих `TextRules.IsFunctionalAct(pattern.Act)` и `pattern.Fact`/`pattern.Recall`: консервативный unsupported, никаких вымышленных игровых действий/сохранения памяти.
5. Повторные ответы: только успешно выбранный/really displayed TemplateId помечается недавним. Если все безопасные шаблоны недавно показаны, осознанно выбрать проверяемый повтор существующего шаблона с диагностикой (как отдельный approximate repeat fallback), а не ошибочно заявить отсутствие шаблонов. Transactional copy-commit уже существует, его нельзя ломать.
6. `DialogueLabSession` принимает итог из инспектора по явной проверяемой причине/статусу, а не по сравнению рендеренного текста с сырым XML и не по наличию `{` в первом TEMPLATE. Если понадобится расширить `PreviewResult`, сделай обратносуместимый contract и обнови все потребители. Сохранить точные IDs и `PackFingerprint`.
7. `NO_PACK_MATCH` означает отсутствие распознанного PATTERN, а не отсутствие подходящего ответа. Другие причины обязаны отличаться. Не выдавать C# предположение за Java runtime parity.
8. Адвайзорный world: `пвп`/`pvp`/самые очевидные варианты допустимо детерминированно распознавать как GAME, **не** превращая это в автоматическое сопоставление PATTERN и не меняя исходный input.
9. Существующий `MainForm` legacy preview (`tabChat`) по возможности использует ту же безопасную политику. Не переписывать WinForms Designer/Layout в задаче PSS-010. Изменения GUI — только если диагностически необходимы для честных статусов.

## Запрещено

- Писать в L2J, патчить Java/manifest/XML/custom, менять candidates, approvals, staging, HMAC proof, corpus DB или chat archive.
- Генерировать новые фразы по Gemma в ответе PACK; смешивать MENTOR и PACK; фальсифицировать persona/memory/fact.
- Включать functional/gameplay response через «похожий» текст или угадывание act.
- Убирать подробные `NOT_JAVA_RUNTIME_PARITY` и `WORLD_ADVISORY_ONLY` статусы.
- Изменять `InitializeComponent` или добавлять runtime BuildUi для этой Core-ошибки.
