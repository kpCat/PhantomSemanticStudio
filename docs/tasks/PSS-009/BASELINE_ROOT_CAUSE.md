# PSS-009 — реально наблюдаемый дефект и проверяемая гипотеза

## Пользовательские скриншоты 2026-10-09 (файлы изображений намеренно НЕ включены в Git)

При фактическом запуске Studio и чтении High Five пользователь показал 4 экрана главного окна (~1260px шириной):

- **Библиотека:** поиск и таблица расползаются вправо, правая часть таблицы/колонка текста обрезана, кнопка `btnPackQuality` («Карта качества / ёмкость (advisory)») вообще не видна.
- **Экспорт для ревью:** readonly текст пояснений обрезается справа, элементы расположены вне корректной доступной ширины; проверить нижний `txtExportLog`, `btnV3Proposal`, `btnStageXml`.
- **Кандидаты:** видимый интерфейс не доказывает отсутствие нижних/правых выходов; требуется реальный геометрический аудит кнопок, в том числе `btnFindSimilar`/`btnSemanticReview`.
- **Диалог и обучение:** `txtConversation` виден слева и огромная пустая/невидимая зона справа; ввод, уточнения и кнопки действий ниже видимого окна. Отдельный `grpLessons` может оказаться вне viewport.
- **Конструктор** (предыдущий скрин после импорта): `grpRequest`/`txtInstruction` разрослись во всю видимую страницу, генераторные кнопки ушли под нижнюю границу.
- **Настройки** ранее выглядели частично рабочими, но эту страницу обязательно проверить точно так же.

## Что непосредственно видно в опубликованном коде (base cddf9a65ffc5b052c110b264c4fe3973f8e6a37c)

Файл `src/PhantomSemanticStudio.WinForms/MainForm.Designer.cs`:

- `tabs.Size = new Size(1260,734)`, `tabs.Dock = Fill`, `MainForm.ClientSize = (1260,850)`.
- Все `tabGenerate`, `tabChat`, `tabLibrary`, `tabExport`, `tabSettings` созданы через `new TabPage()` и **не имеют явно установленного начального `.Size`** внутри `InitializeComponent()`.
- Только `tabCandidates.Size = new Size(1252,712)` присутствует (строка примерно 195).
- Контролы на проблемных страницах имеют большие координаты и `Anchor.Right`/`Anchor.Bottom`, например:
  - `btnPackQuality`: Location(866,58), Size(360,30), Anchor=Top|Right;
  - `gridLibrary`: Location(16,96), Size(1210,350), Anchor=Top|Bottom|Left|Right;
  - `grpRequest`: Location(16,54), Size(764,538), Anchor=Top|Bottom|Left|Right;
  - `btnGenerate`: Location(16,614), Anchor=Bottom|Left;
  - `txtChatInput`: Location(16,402), Anchor=Bottom|Left|Right;
  - `btnPreview`: Location(1060,402), Anchor=Bottom|Right.
- `AutoScaleMode=Font`, `AutoScaleDimensions=(7,17)`, `Font=Segoe UI 10`, `MinimumSize=(1276,810)`. Остальные отдельные Designer формы по большей части `AutoScaleMode=Dpi`, `(96,96)`.

## Гипотеза PSS-009-A (подтвердить тестом, НЕ выдавать за уже доказанный runtime root cause)

Когда TabPage сначала имеет маленький исходный размер (в WinForms default может быть ~200×100), а контролы Anchor расположены так, будто Page уже 1252×712, первое изменение TabPage размера приводит к ошибочному пересчёту якорей. Например, при Δwidth=1052 `gridLibrary.Width` может стать ~2262 вместо 1210; `btnPackQuality.X` может сдвинуться ~1918; при Δheight=612 кнопки внизу уйдут за viewport. Так выглядит конкретно наблюдаемая ошибка.

**Что должен сделать Codex**: до правки снять фактические `TabPage.ClientSize` и `Bounds` критических контролов при создании, первом Show, первом и повторном переключении вкладки, window resize. Если цифры подтвердят гипотезу, исправить исходный sizing/layout baseline в Designer так, чтобы якоря пересчитывались от верной геометрии. Если цифры не подтвердят — диагностика DPI/auto-scale/dock order/AutoScroll и новая проверяемая гипотеза; никакого случайного перебора размеров.

## Отдельное ограничение

`MainForm.MinimumSize=(1276,810)` физически выше дисплея 1366×768 и ряда scaled viewports. Это *не доказанная первопричина текущего дефекта*, но самостоятельный accessibility risk: обеспечить разумные minimum/layout или доступную прокрутку без искусственного увеличения размеров окна. Не исправлять «не видно» скрытием контролов, выключением кнопок или уменьшением шрифта.
